# OilPress CRM — CRM для небольшого производства со встроенным ИИ-помощником

Рабочая система для маслобойни (масла холодного отжима): заказы, клиенты, задачи, остатки,
**планирование загрузки прессов** и **ИИ-помощник**, который видит всю базу, разбирает заявки
клиентов из мессенджеров и голосом, отвечает на вопросы о бизнесе и готовит действия — человек
только подтверждает их кнопкой.

Сделана под реальное производство (2 пресса, продажи напрямую, через Avito и Ozon), но построена на
общих сущностях — товар/вариант, клиент, заказ, партия, норма выхода — и переносится на любое
малое производство: сыроварню, пекарню, мыловарню, кофейную обжарку.

## Что умеет

**Запись заказа за полминуты**
- Свободный текст или голос: «Анна, 8 905 777-66-55, две по пол-литра льняного и литр тыквенного,
  заберёт в субботу» → ИИ раскладывает текст по полям, сверяет масла и объёмы с прайсом,
  находит клиента в базе, ставит дату. Человек проверяет форму и жмёт «Записать».
- Лента ближайших дней, как календарь в телефоне: видно, что уже записано на каждый день, статус
  меняется прямо из списка.
- Масла — плитками с поиском, объёмы — кнопками с ценой. Значений по умолчанию нет, поэтому
  «случайного» заказа не будет.
- Клиент по телефону без дублей: «8 926…» и «+7 926…» — один человек.

**Производство**
- Остатки готового масла: произведено партиями − отгружено, резерв под открытые заказы.
- **План прессов**: дефицит под каждый открытый заказ раскладывается по прессам и рабочим дням
  с учётом мощности (прессы × закладки в день), нормы закладки, отстаивания и уже записанных партий.
  Сразу видно, что не успеваем, что просрочено и сколько семян закупить.
- Учёт партий, расходов, норм закладки, себестоимость и прибыль по партиям.

**CRM**
- «Сегодня»: выручка и чистая прибыль месяца, отгрузки на сегодня, просрочки, кто ждёт
  предоплату, ближайшие 7 дней, задачи, что отжать.
- Карточка клиента: история заказов, любимые масла, средний чек, журнал звонков и переписки, задачи.
- Задачи с напоминаниями, привязкой к клиенту и заказу.
- Роли и личные входы сотрудников (администратор / менеджер).

**ИИ-помощник** — панель на любом экране и отдельная страница
- Отвечает на вопросы по базе: «выручка этого месяца против прошлого», «кто из постоянных давно не
  заказывал», «какое масло даёт больше прибыли» — сам пишет SQL только на чтение.
- Знает производство: «когда успеем 10 л льняного?», «что отжимать завтра?» — смотрит план прессов.
- Готовит действия: заказ, задачу, смену статуса, заметку о звонке, расход, запись о партии.
  Каждое действие приходит **карточкой с кнопкой «Подтвердить»**, само ничего не меняет.
- Понимает надиктованный текст: «поллитровая», «пару бутылок», телефон группами цифр.
- Помнит контекст экрана: в карточке клиента «этот клиент» = открытый клиент.

## Как устроен ИИ и почему он безопасен

```
вопрос/заявка → агент (LLM) ⇄ инструменты ──► чтение: SQL, сводка, клиенты, остатки, план прессов
                                         └──► изменения: черновик → кнопка «Подтвердить» → запись
```

- **Агентный цикл на JSON-протоколе** (`assistant.py`): модель на каждом шаге либо вызывает
  инструмент, либо отвечает. Работает с любым OpenAI-совместимым адресом (шлюз novpnai,
  OpenRouter) без нативного tool calling.
- **SQL только на чтение, два рубежа** (`sql_safety.py`): валидатор пропускает один SELECT/WITH
  без записи, комментариев, `INTO OUTFILE`, `LOAD_FILE`, `SLEEP`, блокировок, системных схем и
  служебных таблиц (пароли, ключи) и корректно разбирает экранирование `\'`. Запрос выполняется
  внутри `START TRANSACTION READ ONLY` с `MAX_EXECUTION_TIME`.
- **Изменения — только через подтверждение**: инструмент проверяет данные по базе (масло есть в
  прайсе, клиент существует, дата корректна), сохраняет черновик и показывает человеку итог.
  Повторный клик не создаст два заказа. Удалять помощник не умеет совсем.
- Названия масел и объёмы сверяются с прайсом детерминированно, а не «на слово» модели.

## Технологии

- **Backend:** Python, FastAPI, MySQL 8 (mysql-connector), токены входа (HMAC), пароли pbkdf2.
- **Frontend:** React 19, React Router, Vite; адаптив под телефон, светлая и тёмная тема,
  распознавание речи через Web Speech API.
- **ИИ:** любая OpenAI-совместимая модель; по умолчанию `google/gemini-2.5-flash` через шлюз novpnai.
- **DevOps:** Docker Compose, GitHub Actions → GHCR → автодеплой на сервер.
- **Тесты:** pytest — 90+ тестов: безопасность SQL, вход и роли, агентный цикл, разбор заказа,
  планировщик.

## Быстрый старт

```bash
cp .env.example .env            # впишите OPENROUTER_API_KEY, иначе ИИ выключен
docker compose up -d --build    # http://localhost:8000
```

Первый администратор создаётся из `OIL_ADMIN_USER` / `OIL_ADMIN_PASSWORD`. **После первого входа
смените пароль:** «Управление → Пользователи → Мой пароль».

Демо-данные для показа (вымышленные клиенты, 100+ заказов, партии, расходы) — только в пустую базу:

```bash
DB_PORT=3307 python scripts/seed_demo.py --yes
```

Разработка фронтенда: `cd frontend && npm install && npm run dev` (http://localhost:5173, API
проксируется на :8000). Тесты бэкенда: `python -m pytest tests`.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `OPENROUTER_API_KEY` | Ключ LLM-шлюза (novpnai `gw-…` или OpenRouter `sk-or-…`). Без него ИИ выключен. |
| `OIL_LLM_URL` | Адрес `/chat/completions`. По умолчанию шлюз novpnai. |
| `OIL_AGENT_MODEL` | Модель агента, по умолчанию `google/gemini-2.5-flash`. |
| `OIL_SECRET_KEY` | Ключ подписи токенов. Если пуст — генерируется и хранится в базе. |
| `OIL_ADMIN_USER`, `OIL_ADMIN_PASSWORD` | Первый администратор (только на пустой таблице пользователей). |
| `OIL_BUSINESS_PROFILE` | Описание бизнеса для ИИ (или поле в «Управление → Настройки»). |
| `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` | Подключение к MySQL. |

## API (основное)

- `POST /api/auth/login` → `{token, user}`; дальше `Authorization: Bearer <token>`.
  Basic-авторизация по-прежнему принимается для старых страниц и скриптов.
- `GET /api/crm/dashboard` — сводка дня; `GET|POST /api/crm/orders`, `PATCH /api/crm/orders/{id}`.
- `GET|POST /api/crm/customers`, `GET|PATCH /api/crm/customers/{id}`,
  `POST /api/crm/customers/{id}/interactions`.
- `GET|POST /api/crm/tasks`, `PATCH|DELETE /api/crm/tasks/{id}`.
- `GET /api/crm/stock`, `GET /api/crm/production-needs`, `GET /api/crm/production-schedule`,
  `GET|PATCH /api/crm/settings` (прессы, рабочие дни, отстаивание, описание бизнеса).
- `POST /api/assistant/chat` — диалог с агентом; `POST /api/assistant/parse-order` — текст → черновик
  заказа; `POST /api/assistant/actions/{id}/confirm|cancel`.
- Старые ручки (`/api/orders`, `/api/order`, `/api/admin/*`, `/api/analytics/*`) сохранены.

## Структура

```
main.py          FastAPI: старые ручки + подключение модулей
auth.py          пользователи, роли, токены, вход
crm.py           клиенты, заказы, задачи, остатки, план прессов, сводка дня
assistant.py     ИИ-агент: инструменты, черновики действий, разбор заказа из текста
sql_safety.py    проверка и read-only выполнение SQL от ИИ
Database.py      исходный слой данных (прайс, партии, расходы, аналитика)
frontend/src     React-интерфейс (components/, components/assistant/, lib/)
scripts/         seed_demo.py — демо-данные
tests/           pytest
```
